# One world slot, two planets: RunSave carries a record per planet

Leaving Planet abandons Desertis but must not destroy it: the Base, farms, caches and world edits stay intact for Phase 3's homecoming, and the same run must still Export/Import as one file. Decided: a run (one localStorage key, one export file) holds one global run state plus a **world record per planet** — each with its own seed, chunk deltas, rotations, chests, crops, fires, Grid state, Ships, Pins and explored-map data; the save version bumps to v3 and v2 saves migrate by wrapping their planet-scoped fields as the Desertis record. Rejected: replacing the run's world on jump (loses the Base and the Phase-3 hook), and separate world slots per planet (breaks one-file Export/Import and splits the run). Consequence: every coordinate-keyed map in Game is planet-scoped at runtime — the planet switch swaps the whole active record, never individual keys.
